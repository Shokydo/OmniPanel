# Бэкапы и синхронизация

## Бэкапы

Кнопка «Создать бэкап» собирает **`.7z`** — LZMA2, `-mx=9`, твёрдый блок: это заметно плотнее zip,
а на сервере с тысячами мелких файлов разница в разы. `7za.exe` едет внутри панели, ставить
7-Zip не нужно; если он всё же не запустился, бэкап соберётся zip'ом.

* в списке бэкапов у каждого архива виден формат (`7z, максимум сжатия` / `zip`);
* в консоль пишется имя файла, размер, из какого объёма сжат и во сколько раз плотнее;
* восстанавливаются `.7z`, `.zip` и `.tar.gz` — кнопка одна;
* `.7z` открывается и в редакторе файлов: список содержимого, чтение файла без распаковки,
  «распаковать один файл» и «распаковать всё».

* Хранится столько копий, сколько указано в настройках; старые удаляются сами.
* Есть авто-бэкап по расписанию и бэкап перед запуском.
* Восстановление: «Восстановить» — панель сначала сделает бэкап текущего состояния.

## Синхронизация с GitHub

В окне сервера, блок «Синхронизация». По умолчанию включено «весь сервер»:

* **уходит** — мир, плагины, конфиги, ядро, `server.properties`;
* **не уходит** — логи, кэш, бэкапы, `libraries`.

Два режима:

| Режим | Как работает |
|---|---|
| Пофайлово | каждый файл отдельным блобом, изменения считаются по хешу |
| Одним архивом | весь сервер → `.omnipanel/сервер.zip` + `.omnipanel/манифест.json`, лимит 95 МБ |

Режим архива удобен для больших серверов и для переезда на другую машину: там достаточно
«Забрать с GitHub», и панель распакует архив сама.

## Вход в GitHub

Два способа: **по коду** (кнопка «Вход по коду» — панель показывает код и ждёт подтверждения
в браузере) и **токеном** (запасной вариант, строка раскрывается кнопкой).
Свой OAuth App заводить не нужно — используется встроенный публичный Client ID.

## Ошибка 409 на пустом репозитории

Гитхаб отвечает `409 Git Repository is empty`, когда в репозитории нет ни одного коммита.
Панель делает первый коммит через Contents API, получает ветку и повторяет отправку —
409 больше не появляется даже на свежем пустом репозитории.
