# Бэкапы и синхронизация

## Бэкапы

Кнопка «Создать бэкап» собирает **`.7z`** (LZMA2, максимум сжатия) — 7-Zip едет внутри панели.
Список бэкапов обновляется сразу, в консоль пишется имя файла, из какого объёма сжат и во сколько
раз плотнее. Старые `.zip` восстанавливаются так же, как новые `.7z`.

* Хранится столько копий, сколько указано в настройках; старые удаляются сами.
* Есть авто-бэкап по расписанию и бэкап перед запуском.
* Восстановление: «Восстановить» — панель сначала сделает бэкап текущего состояния.

## Синхронизация с GitHub

Пересылка идёт **одним архивом** — так включено по умолчанию.

### Отправка: архивация → GitHub

1. Панель упаковывает папку сервера в архив (`.7z`, LZMA2 — тот же архиватор, что у бэкапов).
2. Получившийся файл кладётся в репозиторий одним файлом: `.omnipanel/сервер.7z`
   плюс `.omnipanel/манифест.json` со временем, числом файлов и контрольной суммой.
3. В строке состояния видно оба шага: «шаг 1 из 2: архивирую сервер…», затем
   «шаг 2 из 2: отправляю архив на GitHub», и в конце — размер и коммит.

Если на GitHub уже лежит такой же архив, панель пишет «отправлять нечего» и ничего не коммитит.

### Забор: архив с GitHub → распаковка

1. Панель скачивает файл из репозитория («шаг 1 из 2»).
2. Распаковывает его в папку сервера («шаг 2 из 2») — с полной перезаписью файлов из архива.

Понимается и новый `.7z`, и `.zip` из прошлых версий панели: старые репозитории продолжают
работать, а при следующей отправке панель сама заменит zip на 7z.

### Что попадает в архив

* **уходит** — мир, плагины, конфиги, ядро, `server.properties`;
* **не уходит** — логи, кэш, бэкапы, `libraries`, `.git`.

### Отправка по файлам

Если нужен пофайловый diff в репозитории (например, чтобы смотреть изменения в веб-интерфейсе
GitHub), выключи переключатель «пересылать сервер одним архивом». Тогда каждый файл едет отдельно,
изменения считаются по хешу. Для больших миров архив надёжнее: десятки тысяч мелких файлов
превращаются в один, и лимит GitHub на размер файла проверяется один раз.

### Вход в GitHub

Два способа: **по коду** (кнопка «Вход по коду» — панель показывает код и ждёт подтверждения
в браузере) и **токеном** (запасной вариант, строка раскрывается кнопкой).
Свой OAuth App заводить не нужно — используется встроенный публичный Client ID.

### Ошибка 409 на пустом репозитории

Гитхаб отвечает `409 Git Repository is empty`, когда в репозитории нет ни одного коммита.
Панель делает первый коммит через Contents API, получает ветку и повторяет отправку —
409 больше не появляется даже на свежем пустом репозитории.
