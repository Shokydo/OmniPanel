==========================================================
  OmniPanel 1.11.1 — portable версия для Windows
==========================================================

УСТАНОВКА ОДНИМ EXE (самый простой путь)
  1. Запусти файл OmniPanel-Установка-<версия>.exe
     (внутри уже лежит вся панель, ничего качать не надо).
  2. В чёрном окне написано, что и куда ставится. Внизу — кнопки:
     «Установить» (главная), «Изменить путь…», «Отмена».
     Enter — тоже установка, Tab — переход между кнопками,
     Esc — отмена, мышь работает.

     ПАПКА УСТАНОВКИ: по умолчанию %LOCALAPPDATA%\OmniPanel.
     Хочешь на другой диск — нажми «Изменить путь…», выбери папку
     (например D:\Games) и панель встанет в D:\Games\OmniPanel.
     Выбранная папка запоминается: следующий запуск этого exe
     откроется уже с ней, обновления и переустановка попадут туда же.
     Забыть путь: удали файл %LOCALAPPDATA%\OmniPanel-setup\install-path.txt
     Без диалога: OmniPanel-Setup.exe --dir "D:\Games"
  3. Панель распакуется в %LOCALAPPDATA%\OmniPanel, появятся ярлыки
     на рабочем столе и в меню "Пуск", включится автопроверка
     обновлений, панель запустится.
  4. Запустишь этот же exe ещё раз — он просто откроет установленную
     панель (ярлык не нужен).
  Права администратора не нужны. Удалить панель = удалить папку
  %LOCALAPPDATA%\OmniPanel. Переустановить: тот же exe с ключом
  --reinstall (настройки и миры останутся).

  ЧТО НЕ СЛЕТАЕТ ПРИ ОБНОВЛЕНИИ
    Обновление меняет только код панели (папку resources\app).
    Рядом лежит OmniPanelData — её не трогают:
      servers.json    - список серверов, команды, пути к мирам
      panel.json      - профиль GitHub, настройки обновлений
      Local Storage   - тема, фон, масштаб, звуки
      tps, backups    - история TPS и бэкапы миров
      logs            - логи консоли
    Сами миры серверов лежат в твоих папках — их обновление
    вообще не касается.
    Перед заменой всё копируется в OmniPanelData\updates\backup,
    а если панель раньше работала из другой папки, установщик
    найдёт старый OmniPanelData и предложит перенести данные.

ЗАПУСК
  1. Распакуй ВСЮ папку целиком (не запускай exe из архива!)
  2. Запусти OmniPanel.exe
  3. Ничего устанавливать не нужно: Node.js и Electron уже внутри

ПЕРВЫЙ ЗАПУСК
  Панель стартует в трее (значок рядом с часами).
  Клик по значку: свернуть/развернуть окно.
  Правый клик по значку: быстрое управление всеми серверами.

ДОБАВИТЬ СЕРВЕР
  Кнопка "+ Добавить существующий" слева внизу (сервер уже есть на диске).
  Нет сервера? Кнопка "Создать сервер" — панель скачает ядро и всё настроит
  (подробности ниже, раздел "ЧТО НОВОГО В 1.4").


ЧТО НОВОГО В 1.11 — ПАНЕЛЬ ОБНОВЛЯЕТСЯ САМА ИЗ GITHUB

  Эта сборка ставится вручную последний раз: дальше панель
  обновляет себя сама (Настройки панели -> Обновления).

  Больше не надо каждый раз качать архив целиком.
  Панель смотрит в твой публичный репозиторий и предлагает новую версию.

  КАК ВКЛЮЧИТЬ (один раз)
    1. Репозиторий уже есть: Shokydo/OmniPanel (публичный).
    2. Панель -> Настройки панели -> вкладка "Обновления":
         репозиторий: Shokydo/OmniPanel   (подставлен сам)
         ветка:       main
         галочка "Проверять обновления при запуске" — включена
    3. Всё. Токен не нужен, репозиторий публичный.

  КАК ЭТО РАБОТАЕТ
    - при запуске панель тихо проверяет канал (через пару секунд);
    - если есть новее — уведомление и точка на вкладке "Обновления";
    - кнопка "Обновить и перезапустить" качает маленький архив (~1 МБ,
      а не 105 МБ), заменяет файлы панели и перезапускается;
    - перед заменой старые файлы копируются в
      OmniPanelData\updates\backup\before-<версия>-<время>
      (хранятся два последних, кнопка "Папка бэкапов" их открывает);
    - пока запущен хотя бы один сервер, обновление не ставится —
      сначала останови серверы;
    - полная сборка (новый exe) качается по кнопке "Скачать полную сборку":
      рядом с папкой программы появится "Обновить-OmniPanel.bat" —
      запусти его, он закроет панель, распакует новую версию и запустит её.

  КАК ВЫКЛАДЫВАТЬ НОВУЮ ВЕРСИЮ (для того, кто собирает)
    В папке программы с исходниками:
        node tools/make-update.js --notes "что нового"
      (или ярлык "7-Собрать-обновление.bat")
    Появится набор: dist\OmniPanel-обновление-<версия>.zip
      - распакуй его и запусти "Залить-обновление.bat";
      - скрипт возьмёт токен из настроек панели (Настройки -> GitHub),
        зальёт update.json и архив кода в репозиторий и создаст релиз;
      - полную сборку приложит к релизу, если положить
        OmniPanel-win64.zip в папку dist рядом.

    Вручную (если скрипт не подошёл):
        update.json               -> в корень репозитория
        dist\OmniPanel-code.zip   -> в папку dist репозитория
        OmniPanel-win64.zip       -> файлом к релизу v<версия>


ЧТО НОВОГО В 1.10 — ПОЛНЫЙ СЕРВЕР, ВХОД В GITHUB, НАСТРОЙКИ ПО КАТЕГОРИЯМ

  СИНХРОНИЗАЦИЯ ВСЕГО СЕРВЕРА
    Режим по умолчанию: "весь сервер (мир, плагины, конфиги, ядро)".
    Теперь в репозиторий едут и jar-файлы: ядро сервера и плагины.
    Не отправляются по-прежнему: логи, крэш-репорты, session.lock,
    zip/tar/gz/7z-архивы. Нужен только мир — выбери режим пониже.

  ВХОД В GITHUB
    Настройки панели -> вкладка "GitHub":
      1. Вставь токен (права "repo") -> кнопка "Войти".
      2. Панель подгрузит список твоих репозиториев (есть поиск).
      3. Клик по репозиторию подставит его в настройки синхронизации.
      4. Кнопка "Создать приватный" заводит новый репозиторий сразу.
    Токен аккаунта используется всеми серверами: отдельное поле
    "Свой токен" в настройках сервера больше не обязательно.

  НАСТРОЙКИ ПАНЕЛИ ПО КАТЕГОРИЯМ
    Окно настроек разбито на вкладки (с 1.11 добавилась восьмая —
    "Обновления"):
      Оформление   - темы, свои цвета, сохранение темы по имени, форма
      Фон          - обои, свой файл, история недавних фонов
      Эффекты      - цвет, насыщенность, прозрачность, размытие подложки
      Окно         - режим запуска, автозапуск, масштаб интерфейса
      Уведомления  - тумблеры, мягкий звук, время показа 2/4/7 секунд
      GitHub       - вход, репозитории, создание нового
      Звуки        - тумблер, громкость, кнопки проверки звука

  ГЛУБИНА СКАНИРОВАНИЯ — КНОПКА
    В окне поиска серверов вместо выпадающего списка кнопка с иконкой
    папки: щелчок переключает 4 -> 5 -> 7 -> 10 уровней. Точки справа
    показывают выбранную ступень, значение запоминается.

  ПЕРЕКЛЮЧАТЕЛИ ВМЕСТО ГАЛОЧЕК
    Все галочки в настройках заменены тумблерами вкл/выкл.

  КРАКОЗЯБРЫ В ЛОГАХ ИСПРАВЛЕНЫ
    Строки вида "╟руЁєцхэю ЄЁшуухЁют яЁефьхЄют: 0" появлялись, когда
    cp1251-байты читались как cp866. Теперь такие строки распознаются
    и восстанавливаются: "Загружено триггеров предметов: 0".
    Рамки "════" из логов при этом не портятся.


ЧТО НОВОГО В 1.9 — СИНХРОНИЗАЦИЯ ЧЕРЕЗ GITHUB
  КАК ЭТО РАБОТАЕТ
    Друг выключил сервер -> мир сам уехал в репозиторий.
    Ты запускаешь сервер позже -> панель проверяет GitHub, качает
    изменения и только потом запускает ту же версию мира.

  НАСТРОЙКА
    1. Создай ПРИВАТНЫЙ репозиторий на GitHub (например friend/world).
    2. GitHub -> Settings -> Developer settings -> Personal access tokens
       -> токен с галочкой "repo".
    3. Панель -> настройки сервера -> "Синхронизация с GitHub":
       включить, вписать владелец/репозиторий, ветку и токен.
    4. Выбрать, что синхронизировать: весь сервер / мир + конфиги
       плагинов / только мир (по умолчанию — весь сервер).
    5. Кнопки "Проверить", "Скачать", "Отправить" — для ручной проверки.

  ЧТО ПРОИСХОДИТ
    - перед запуском: проверка обновлений, скачиваются только
      изменившиеся файлы (весь мир каждый раз не гоняем);
    - после остановки: мир автоматически отправляется новым коммитом;
    - такие серверы показываются отдельной группой "ОБЩИЕ · GITHUB";
    - кнопки "Запустить все / Остановить все / Перезапустить все" их
      НЕ трогают — чтобы случайно не перезапустить чужой мир;
    - в контекстном меню общего сервера: "Обновить из GitHub и запустить",
      "Скачать изменения", "Отправить на GitHub";
    - логи, session.lock и архивы не синхронизируются; с 1.10 режим
      "весь сервер" включает ядро и jar-файлы плагинов;
    - git на компьютере не нужен, работает через GitHub API;
    - конфликты не сливаются: побеждает тот, кто отправил последним.

  ПЕРЕНОС ПАПКИ В ПАПКУ ПРОГРАММЫ
    Настройки сервера -> "Папка программы" -> "Перенести сюда".
    Папка копируется в server\имя_сервера рядом с OmniPanel.exe,
    путь сервера обновляется, старую папку можно сразу удалить.

    Полезные команды (/mm reload, /mm m spawn, /mm i get ...).
  Кнопка "Вставить" кладёт шаблон в позицию курсора,
  "Новый файл по шаблону" создаёт файл по верному пути
  (например plugins/MythicMobs/Mobs/MyMob.yml).
  Полная вики: wiki.mythiccraft.io


ЧТО НОВОГО В 1.4 — СОЗДАНИЕ СЕРВЕРА ИЗ ПАНЕЛИ
  Новая кнопка "Создать сервер" в сайдбаре (и на пустом экране).
  Больше не нужно искать jar-файл руками: панель сама скачает ядро
  по прямой ссылке с официального API и подготовит папку сервера.

  ЯДРА (10 вариантов):
    Оптимизированные : Paper, Folia, Purpur
    Моды             : Fabric, Forge, NeoForge
    Официальные      : Vanilla
    Прокси           : Velocity, Waterfall
    Другое           : Своя ссылка на любой jar (https://...)

  ВЕРСИИ подтягиваются в реальном времени с API ядра.
  Рядом с версией написано, какая Java нужна.

  JAVA ищется автоматически: PATH, JAVA_HOME, C:\Program Files\Java,
    Eclipse Adoptium, Amazon Corretto, Microsoft jdk, Zulu, BellSoft.
    Если версия ниже нужной — об этом честно написано.
    Кнопка "где взять Java?" открывает Adoptium Temurin,
    кнопка "⟳" переискивает Java после установки.

  ЧТО НАСТРАИВАЕТСЯ:
    - папка создания (кнопка "обзор..." — системный Проводник);
    - название в панели, порт, MOTD, online-mode;
    - память: минимум и максимум (-Xms / -Xmx) в мегабайтах;
    - флаги JVM: Aikar (по умолчанию), простые G1GC, без флагов
      или свои.

  ЧТО СОЗДАЁТСЯ:
    - jar ядра (скачивается с полосой прогресса и объёмом в МБ);
    - start.bat: chcp 65001, cd /d "%~dp0",
      java -Xms... -Xmx... <флаги> -jar "..." nogui, pause;
    - eula.txt с eula=true (сервер сразу стартует);
    - server.properties: порт, MOTD, online-mode, max-players,
      difficulty.
    Путь к Java с пробелами берётся в кавычки, кириллица в MOTD
    экранируется — старый Minecraft не покажет "кракозябры".

  Готовый сервер сразу появляется в списке панели с командой запуска,
  командой остановки "stop" и включённым TPS-монитором — жми "Старт".

  FORGE / NEOFORGE: панель скачивает установщик и запускает его
    (--installServer) прямо в папке сервера — это занимает несколько
    минут, нужна установленная Java.

  Если сервер уже есть — всё как раньше: "+ Добавить существующий".

ЧТО НОВОГО В 1.3
  - СКАНЕР ИСПРАВЛЕН: раньше он не находил серверы, у которых нет
    "серверных" jar-файлов (папки с одним start.bat / server.exe),
    а папка с плагинами блокировала спуск вглубь. Теперь:
      * скрипт запуска (start.bat, run.bat, server.cmd ...) сам по себе
        считается признаком сервера;
      * .exe-серверы ищутся по умолчанию (чип "exe-серверы");
      * из папок "плагинов" сканер продолжает спуск вглубь,
        поэтому вложенные серверы находятся;
      * плагины больше не мешают: они идут в конце списка
        и помечены как "плагины";
      * глубина по умолчанию 5 (было 4), можно выбрать до 10;
      * скорость выросла в несколько раз (48 папок параллельно,
        пропуск "висящих" папок через таймаут).
  - Полоса прогресса сканирования: реальный процент, сколько папок
    просмотрено, сколько в очереди, сколько найдено и ПОЛНЫЙ ПУТЬ
    папки, которую сканер читает прямо сейчас.
  - Новая кнопка "9 квадратиков" в шапке (и рядом с "Сканировать"):
    сетка всех серверов. В карточке: иконка, статус, uptime, CPU/RAM,
    кнопки Старт/Стоп/открыть папку. Есть поиск по названию/пути,
    "Запустить все"/"Остановить все" и ПКМ-меню прямо в сетке.

ЕСЛИ В КОНСОЛИ КРАКОЗЯБРЫ
  Настройки сервера -> "Кодировка вывода":
     Авто        - обычно этого хватает
     CP866       - консоль Windows, старые плагины/батники
     CP1251      - логи в Windows-1251
     UTF-8       - Linux-серверы
  С 1.10 каждая строка дополнительно проверяется на двойное
  перекодирование (те самые "╟руЁєцхэю") и чинится автоматически.

TPS ДЛЯ MINECRAFT
  Настройки сервера -> поле "TPS-монитор": команда (по умолчанию tps)
  и интервал опроса (по умолчанию 30 c). Ответ Paper/Spigot
  ("TPS from last 1m, 5m, 15m: ...") и Forge ("Mean TPS: ...")
  распознаётся автоматически.

ДАННЫЕ
  Настройки серверов:  LocalPanelData\servers.json
  Бэкапы:              LocalPanelData\backups\<id сервера>\
  История TPS:         LocalPanelData\tps\
  Переносишь папку на другой ПК — всё едет вместе с ней.

ВАЖНО
  - Если в пути или команде есть пробелы — бери путь в кавычки:
        "C:\My Servers\minecraft\start.bat"
  - Windows SmartScreen может ругаться на неподписанный exe:
        "Подробнее" -> "Выполнить в любом случае"
  - Закрытие окна НЕ останавливает серверы (работают в трее).
    Полный выход: правый клик по значку в трее -> "Выход".

  Смотри консоль в панели — там видно текст ошибки:
  неверная рабочая папка, нет Java в PATH, мало памяти в -Xmx и т.п.
